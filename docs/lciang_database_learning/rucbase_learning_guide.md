# RucBase 学习指南

这份文档的目标不是把仓库“介绍完”，而是帮你把这个项目学明白、学下去。RucBase 是一个教学型数据库系统实验仓库，你可以把它理解成一条从“磁盘上的页”一路走到“SQL 语句执行与并发控制”的完整路线。

如果你是第一次接触数据库内核，建议先记住一句话：

**这个项目的核心不是 SQL 语法本身，而是“如何把数据安全、快速、正确地存起来、取出来、改掉，并在多个事务同时访问时仍然保持正确”。**

---

## 1. 这个仓库是什么

RucBase 是面向本科数据库课程实验的教学用数据库管理系统。仓库首页 README 说明了它的实验目标、环境要求和实验文档入口。它的代码结构大致可以分成几层：

- 存储层：负责磁盘文件、页、缓冲池和记录。
- 索引层：负责 B+ 树索引。
- 执行层：负责把 SQL 变成执行计划，并逐步执行。
- 事务层：负责事务、锁和并发控制。
- 恢复层：负责日志和崩溃恢复。
- 系统层：负责数据库元数据和 DDL。

你可以把它看成一个“缩小版数据库内核”。

## 2. 先建立整体心智模型

先不要急着背接口。先建立一个最重要的系统视角。

### 2.1 数据怎么流动

一个 SQL 语句进入系统后，通常会经历这条链路：

1. 客户端把 SQL 发给服务器。
2. 解析器和规划器把 SQL 变成执行计划。
3. 执行器按计划一层层读取表、索引或临时结果。
4. 记录和索引最终都要落到页上。
5. 页先在缓冲池里操作，必要时再刷到磁盘。

用一句更直白的话说：

**SQL 不会直接“改磁盘”，它通常先改内存里的页，最后再通过缓冲池和磁盘管理器落盘。**

### 2.2 并发怎么保证正确

当多个事务同时访问同一份数据时，系统必须保证：

- 读到的数据是合法的。
- 写入不会互相踩踏。
- 事务提交后结果可见，回滚后修改消失。

这就是事务管理、锁管理和日志恢复要解决的问题。

### 2.3 为什么要分层

分层的好处非常实际：

- 底层只关心“页”和“文件”。
- 中层只关心“记录”和“索引”。
- 上层只关心“SQL 怎么执行”。
- 再往上是“事务一致性”和“并发正确性”。

这样每层都能独立测试，错误也更容易定位。

## 4. 代码结构怎么理解

你现在最需要的不是“所有文件都看一遍”，而是知道每个目录在系统里扮演什么角色。

### 4.1 存储层

关键对象通常是：

- DiskManager：负责操作磁盘文件。
- Page：一个固定大小的数据页。
- Replacer：在缓冲池满了以后决定淘汰谁。
- BufferPoolManager：管理内存页和磁盘页之间的交换。
- RmManager / RmFileHandle / RmPageHandle：记录文件和记录操作。

你可以这样理解：

- DiskManager 像“文件柜”。
- BufferPoolManager 像“桌面上的工作区”。
- Replacer 像“桌面不够大时，先把谁挪走”的规则。
- Record Manager 像“在一页里怎么组织一张表的记录”。

### 4.2 索引层

关键对象通常是：

- IxManager：索引文件的创建、打开、删除、关闭。
- IxIndexHandle：B+ 树的具体操作入口。
- IxNodeHandle：B+ 树某个结点的操作。

B+ 树在这里的作用很直接：

- 等值查找快。
- 范围查询也快。
- 适合数据库里“按键找记录”这种高频场景。

### 4.3 执行层

关键对象通常是：

- SmManager：系统管理器，负责元数据和 DDL。
- QlManager：查询执行管理器。
- Planner：生成执行计划。
- AbstractExecutor 及其子类：真正执行某个算子的对象。

查询执行模块采用火山模型。你可以先把它理解成：

**上层算子不断从下层算子“要一条结果”，结果就像一条条流水线往上流。**

这种设计的好处是结构清晰，适合组合；缺点是某些场景下会有额外的函数调用开销。

### 4.4 事务和并发

关键对象通常是：

- TransactionManager：管理事务开始、提交、回滚。
- LockManager：管理锁。
- Transaction：保存事务状态、锁集合、日志相关信息。

并发控制里最重要的思想是两阶段锁。你可以先记住最朴素的版本：

- 事务先加锁，再做事。
- 释放锁不能太早。
- 这样才能避免很多并发异常。

### 4.5 恢复层

关键对象通常是：

- LogManager：负责把日志写进缓冲区并刷盘。
- RecoveryManager：负责分析、重做和撤销。

它解决的是另一个问题：

**系统崩溃后，已经提交的事务不能丢，没提交的事务不能“假装成功”。**

## 5. 推荐学习顺序

我建议你按下面顺序学，不要跳。

### 第一步：环境与测试

先搞清楚怎么编译、怎么跑服务端、怎么跑测试。

重点命令通常是：

```bash
cd build
cmake ..
make rmdb -j4
```

然后按模块跑单测：

```bash
./bin/lru_replacer_test
./bin/buffer_pool_manager_test
./bin/b_plus_tree_insert_test
./bin/b_plus_tree_delete_test
./bin/b_plus_tree_concurrent_test
python src/test/query/query_unit_test.py basic_query_test1.sql
python src/test/concurrency/concurrency_unit_test.py dirty_write_test
python src/test/transaction/transaction_unit_test.py commit_test
```

### 第二步：存储层

先学：

1. DiskManager
2. Replacer / LRU
3. BufferPoolManager
4. Record Manager

理由很简单：后面的索引、查询、事务，最后都要落到页和记录上。

### 第三步：索引层

学 B+ 树的创建、查找、插入和删除。

你学索引时要一直追问三个问题：

- 这个结点里存了什么？
- 什么时候要分裂？
- 什么时候要合并或借位？

### 第四步：系统管理和查询执行

先看 SmManager 怎么管理表和索引，再看 QlManager 如何把 SQL 计划转成一串执行器。

这里最值得理解的是“从 SQL 到算子树”的过程。

### 第五步：事务和并发控制

最后学 TransactionManager、LockManager 和日志。

这部分最容易卡住，因为它既有“状态机”的问题，也有“多线程互斥”的问题。建议结合测试场景理解，不要只看函数实现。

## 6. 各模块该重点学什么

### 6.1 存储管理

先问自己这几个问题：

- 为什么页大小是固定的？
- 为什么要有缓冲池，而不是直接读写磁盘？
- LRU 为什么适合作为替换策略？
- 记录是怎么塞进页里的？

你会慢慢理解到：

- 固定页大小便于管理和对齐。
- 缓冲池减少磁盘 I/O。
- LRU 利用“最近访问过的页大概率还会被访问”的局部性。
- 记录管理把一张表拆成很多页，适合数据库的顺序扫描和随机访问。

### 6.2 索引管理

重点理解：

- 为什么是 B+ 树，不是普通二叉树。
- 叶子结点为什么要链起来。
- 范围查询为什么快。
- 插入删除时为什么会发生分裂、合并和借位。

B+ 树最适合数据库，是因为它既能快速查到单个键，也能顺着叶子结点做范围扫描。

### 6.3 查询执行

重点理解：

- 火山模型是什么。
- 执行器是怎么一层层组合起来的。
- DDL 和 DML 为什么走不同路径。
- 表和索引怎么被查询计划使用。

你可以把执行器想成“一个个流水线工人”，每个工人只做一件事，但能和别的工人组合出复杂查询。

### 6.4 事务和并发控制

重点理解：

- 什么是事务状态。
- begin、commit、abort 各自要做什么。
- 什么是共享锁、排他锁、意向锁。
- 为什么脏读、脏写、不可重复读、幻读要被处理。

这部分最关键的不是接口，而是“什么时候允许别人看见我的修改”。

### 6.5 恢复

重点理解：

- 为什么要先写日志再写数据。
- redo 和 undo 的区别。
- 崩溃后系统怎么判断哪些事务应该重做、哪些应该撤销。

这部分的核心目标是：

**即使机器突然断电，数据库也能回到一个正确状态。**

## 7. 一个更适合你的学习方法

我建议你不要只“看懂”，而是每次都按下面五步学一个模块。

### 7.1 先看测试

先看 `src/test` 里的测试文件。测试会告诉你：

- 这个模块的输入是什么。
- 这个模块的输出应该是什么。
- 哪些边界条件最重要。

### 7.2 再看头文件

头文件通常比实现更重要，因为它告诉你：

- 这个类的职责是什么。
- 哪些接口必须实现。
- 依赖哪些其他模块。

### 7.3 画出数据流

对每个模块都试着回答：

- 数据从哪里来？
- 数据要到哪里去？
- 中间谁负责管理状态？

### 7.4 先实现最底层、最小功能

比如存储层先把基本读写打通，索引层先把查找打通，执行层先把单表查询打通。

### 7.5 再补边界和并发

最后再处理：

- 页面替换。
- 多文件。
- 事务并发。
- 回滚和崩溃恢复。

这样更稳，不容易一开始就陷进复杂细节。

## 8. 学习时最常见的坑

### 8.1 只看实现，不看测试

这是最容易走偏的。数据库实验很多时候是“按测试验收”的，测试比注释更接近真实要求。

### 8.2 一上来就硬啃事务和并发

事务和锁很难，但它们建立在前面的存储和记录机制之上。底层没理解，后面只会越看越乱。

### 8.3 只记接口，不理解状态变化

例如 BufferPoolManager 不只是“读页写页”，它还维护：

- page_table
- free_list
- replacer
- pin_count
- dirty 标记

如果不理解这些状态，代码很难真正读通。

### 8.4 不先看数据结构

例如 B+ 树、页头、记录格式、锁队列，这些都需要先有基本数据结构观念。

## 9. 建议的阶段任务

### 入门阶段

目标：能编译，能跑测试，能说清楚仓库结构。

你应该能回答：

- 服务端和客户端怎么启动。
- build 目录怎么生成。
- 单测怎么跑。

### 存储阶段

目标：能说清楚磁盘、页、缓冲池、记录的关系。

你应该能回答：

- 页为什么要固定大小。
- 为什么要有 LRU。
- 记录为什么要放进页里。

### 索引阶段

目标：能说清楚 B+ 树的查找、插入和删除流程。

你应该能回答：

- 为什么索引能让查询更快。
- 为什么树会分裂或合并。

### 执行阶段

目标：能说清楚一个 SQL 语句如何被拆成执行器。

你应该能回答：

- 什么是火山模型。
- 执行器之间如何组合。

### 并发阶段

目标：能说清楚事务、锁和日志的关系。

你应该能回答：

- 为什么 commit 和 abort 不一样。
- 为什么并发控制需要锁。
- 为什么恢复需要日志。

## 10. 你可以直接照着做的学习计划

### 方案 A：7 天入门版

- 第 1 天：环境、编译、测试跑通。
- 第 2 天：DiskManager 和 Page。
- 第 3 天：Replacer 和 BufferPoolManager。
- 第 4 天：记录管理器。
- 第 5 天：B+ 树索引。
- 第 6 天：查询执行和 SmManager。
- 第 7 天：事务、锁和日志。

### 方案 B：2 周实验版

- 第 1 周：只学存储层，把 Lab1 相关内容吃透。
- 第 2 周：再学索引、查询执行、事务控制，并结合测试文件理解系统整体流程。

如果你以后真要做实验，我建议你优先采用第二种方式，因为它更接近真实开发节奏。

## 11. 最后的建议

你学这个仓库时，最重要的不是“背住所有类名”，而是形成一张脑内地图：

- 数据从哪来。
- 状态存在哪。
- 什么时候刷盘。
- 什么时候加锁。
- 什么时候提交或回滚。
- 什么时候通过索引查，什么时候顺序扫。

只要这张地图建立起来，后面任何一个实验，你都会知道该从哪里下手。
